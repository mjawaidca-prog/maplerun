4. Auth guards & routing rules
Server-side middleware logic — implement in middleware.ts
🔒 Auth guard
  • Any /app/*, /employees/*, /payroll/*, /reports/*, /company requires a valid session
  • No session → redirect to /sign-in?callbackUrl=…
  • After successful sign-in, redirect to callbackUrl or /app
🏢 Company guard
  • All app pages also require a company record linked to the session
  • Session exists but no company → redirect to /onboarding
  • /onboarding itself: if company already exists → redirect to /app
🔒 Plan gate
  • /reports/roe and /reports/roe/[id] require plan === 'accountant'
  • Payroll journal export: same guard
  • Gate triggered → show upgrade modal as overlay (not a redirect); URL does not change
  • Upgrade modal close → return to reports dashboard
5. Timesheet integration
New paths for hourly staff — how they feed into the wizard
ℹ️ The existing wizard assumes salary (flat gross amount per employee). The timesheet system computes gross from rate × hours and pre-fills Wizard step 1. The wizard is unchanged — it just receives computed gross values instead of manually typed ones. Hourly and salaried employees can coexist in the same pay run.
PathEntryData flowOutput
Manual hours entry Wizard step 1 → "Hourly" mode toggle, or direct from sidebar User types reg/OT/stat/vac hours per employee; rate comes from employee profile Gross per employee pre-filled into Wizard step 1 → normal CPP/EI/tax calculation
CSV import Timesheet entry → "Import CSV" button → /payroll/new/import Upload → auto-map columns (employee name, reg_hours, ot, stat_hrs, vac) → review + fix unmatched names → confirm Same as manual: gross pre-filled into Wizard step 1
Mixed run Any entry point Salaried employees keep their flat gross; hourly employees get rate × hours gross. All calculated together in preview step. Single preview screen shows all employees regardless of type
