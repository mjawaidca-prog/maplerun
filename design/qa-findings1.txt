MapleRun Payroll Software — Detailed QA Report
Date Tested: June 20, 2026 | Company Tested: A Jays Accounting | Tester: Claude

Executive Summary
MapleRun is a well-structured Canadian payroll application. The core payroll mathematics are accurate and CRA-compliant. However, several bugs ranging from critical data inconsistencies to minor UI issues were found that should be addressed before launch.

🔴 CRITICAL BUGS
BUG #1 — Payroll Summary Shows No Data Despite 2 Finalized Runs
Location: Reports → Payroll Summary
Observed: "No payroll data yet — Finalize pay runs to see the summary here"
Expected: Should display aggregated wages, deductions, and employer costs from the 2 finalized runs.
Impact: A core reporting feature is broken and unusable.
BUG #2 — "By Employee" Tab in Remittances Shows Wrong Data
Location: Remittances → By Employee tab
Observed: Message says "No pay runs finalized for this period" and the table shows 0 employees with $0.00 in all columns, yet the footer Total CRA column shows $1,794.23 — a contradiction.
Impact: Data inconsistency destroys user trust; the two values directly contradict each other in the same UI.
BUG #3 — Active Employees Shows "0" Despite Finalized Pay Runs
Location: Dashboard, Employees page, and Payroll Run detail pages
Observed: Dashboard shows "0 Active Employees" and Employees page says "No employees yet." However, 2 finalized pay runs each show "1 employee" in the payroll list. The payroll detail view shows "0 employees" and an empty employee table.
Impact: Critical data loss/integrity issue — either the employees were deleted after pay runs were finalized, or there's a referential integrity bug where employee records are not properly linked to historical pay runs.

🟠 MODERATE BUGS
BUG #4 — Pay Group Dropdown Displays Internal Database ID After Selection
Location: New Pay Run → Pay Group combobox
Observed: When the dropdown opens, it shows the human-readable label "Default (biweekly, AB)". After clicking to select it, the field displays the raw database ID: cmq9uee8r0002k4fw0ab76745 instead of the label.
Impact: Confusing and unprofessional; users cannot confirm their selection.
BUG #5 — PD7A Amount Inconsistency Between Reports Page and Remittance Page
Location: Reports hub card vs. Remittances page
Observed: The Reports page shows PD7A remittance as $869.24 (YTD 2026), while the Remittances page consistently shows $1,794.23 for the same period.
Impact: Two screens show different totals for the same figure with no explanation — a user would not know which to trust.
BUG #6 — Audit Log is Empty Despite Activity
Location: Company → Audit Log
Observed: Shows "Audit trail will be populated as you use MapleRun" with no entries, even though 2 pay runs have been finalized, which should generate audit events.
Impact: Audit trail is a compliance feature; if it doesn't log pay run finalizations, it cannot be relied upon.

🟡 MINOR BUGS & UX ISSUES
BUG #7 — Unresolved Template Variable {province} on Dashboard
Location: AJays Accounting company → Dashboard
Observed: Active Employees card subtitle reads "All in {province}" — a raw template placeholder that was never replaced with the actual province value.
Impact: Unprofessional; will be visible to all users of companies where the province variable is not populated.
BUG #8 — Direct Deposit Navigation Link Points to Wrong Page
Location: Sidebar navigation → "Direct Deposit"
Observed: The "Direct Deposit" link has href="/payroll" — the same destination as "Run Payroll" and "Pay Statements." Navigating to it just loads the payroll history page.
Impact: Direct Deposit is listed as a feature but is either not implemented or has a broken route.
BUG #9 — Duplicate "YTD Net Deposited" Widget on Dashboard
Location: Dashboard
Observed: The "YTD Net Deposited — $4,358.97" widget appears twice on the same dashboard — once in the top row and once in the bottom row.
Impact: Clutters the UI and suggests a copy-paste error in layout code. The bottom row likely should have shown a different metric (e.g., YTD Employee Deductions).
BUG #10 — Two Duplicate "northwind" Companies in Account List
Location: Sidebar company switcher
Observed: Two entries both named "northwind" appear in the company list.
Impact: Could cause user confusion about which company they are operating in; data may have been duplicated.
BUG #11 — No Validation Error When Calculating Deductions With No Employees
Location: New Pay Run → Calculate Deductions button
Observed: Clicking "Calculate deductions" when there are no active employees silently does nothing (just scrolls the page slightly). No error toast, alert, or message is shown.
Impact: Poor UX — users are left wondering why nothing happened. A clear message like "Add at least one active employee to run payroll" should appear.

🔴 CRITICAL BUGS — ALL CONFIRMED STILL PRESENT + NEW ONES FOUND

BUG #1 — Payroll Summary Shows No Data ✅ CONFIRMED
Status: Still broken. Navigating to Reports → Payroll Summary for "A Jays Accounting" (which has 2 finalized pay runs) still shows "No payroll data yet — Finalize pay runs to see the summary here." The report is completely non-functional.

BUG #2 — "By Employee" Remittance Tab Shows $0 But Footer Shows $1,794.23 ✅ CONFIRMED
Status: Still present. The By Employee tab shows "No pay runs finalized for this period" with all $0.00 values across the table, yet the totals footer row still shows $1,794.23 in the Total CRA column. This is a direct contradiction on the same screen.

BUG #3 — Employees Show 0 Despite Finalized Pay Runs ✅ CONFIRMED
Status: Confirmed as a data integrity issue. The existing pay runs were processed for 1 employee but that employee record no longer exists in the system. After we created a new test employee (Jane Smith), Active Employees correctly updated to "1" — which confirms the prior employee's record was deleted or orphaned, but their historical payroll data remains. This is a referential integrity issue.

🆕 BUG #12 — Employee Creation Redirects to 404 Page (CRITICAL)
Location: Add Employee → Create employee button
Observed: After successfully filling out the form and clicking "Create employee", the app redirects to /app/employees which returns a 404 "This page could not be found" error. The base URL prefix is wrong — it should redirect to /employees (which works), not /app/employees.
Note: The employee IS created successfully in the background (Jane Smith appeared when navigating manually to /employees), but the user sees a 404 error and has no indication of success. This is a jarring, broken UX flow for a core user journey.

🆕 BUG #13 — Employee Edit Page Returns 404 (CRITICAL)
Location: Employee detail → Edit button
Observed: Clicking "Edit" on an employee's profile navigates to /employees/{id}/edit which returns 404 "This page could not be found". Employees cannot be edited at all — their personal details, TD1, pay group, province, and all other settings cannot be modified after creation. This is a showstopper for any real-world use.

🆕 BUG #15 — TD1 Federal Claim Amount Mismatch ($16,129 vs $16,452)
Location: Employee detail → TD1 claim section
Observed: The auto-generated TD1 profile shows a Federal Claim of $16,129 (default), but the Company Settings → Payroll tab shows the 2026 Federal Basic Personal Amount as $16,452. These should match since a default TD1 uses the BPA. The $323 discrepancy means income tax will be over-withheld by approximately ($323 × 2026 federal marginal rate) per period for each employee.
Tax Impact: The federal income tax withholding will be slightly higher than it should be, meaning employees receive less take-home pay than legally required under the default TD1.

🆕 BUG #16 — Employee Province and Pay Group Not Saved After Creation

After creation, the employee's Province shows "—" and Pay Group shows "—" in both the employee list and the detail page's Pay settings panel. The pay group selection from the creation form was not persisted. This means the employee has no pay group assigned and cannot be included in a payroll run.

🆕 BUG #17 — "1 Action Required / T4 Filing Deadline" Shown on Companies With Zero Payroll
Location: Dashboard for companies with no pay runs (e.g., MAPLE2026)

🆕 BUG #18 — Start Date Auto-Set to Tomorrow (2026-06-21) Instead of Today

🔵 COMPANY SWITCHING — DETAILED FINDINGS (NEW SECTION)
This is an important area for an Accountant plan product where switching between client companies is a core workflow.
What Works: The company data does load correctly when you click a company in the sidebar. The main content area (dashboard heading, statistics, pay runs) all update to the selected company's data. ✓
Bug #19 — Sidebar Highlight Does Not Update on Company Switch (Moderate)
When you click a different company in the sidebar, the red highlight (active indicator) on the sidebar does NOT update to the newly selected company. It remains on whichever company was last fully page-loaded, not the one that was just clicked. For an accountant managing 9+ companies, this creates a dangerous situation where they cannot tell at a glance which company's data they're viewing. The only reliable way to know is to look at the heading text in the main content area.
Bug #20 — Rapid Clicking Causes Incorrect Company to Load (Moderate)
When clicking multiple companies quickly, the sidebar and content area can get out of sync. For example, the content may load Company A's data while the sidebar shows Company B's highlight. This was directly observed during testing.
